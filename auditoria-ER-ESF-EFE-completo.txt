PARTE 2 · C5 — FILTRO DE HOJAS JERÁRQUICAS (nuevo v17)
════════════════════════════════════════════════════════════════════

CAUSA RAIZ CONFIRMADA (evidencia algebraica):
  Dataset: BPWOCONSOL_PE con BP de 6,797 filas (BP2023)
  IO v10:        $99,431,105,412
  IO certificado: $33,081,618,980
  Ratio: 3.006× → tres niveles del árbol PUC sumados simultáneamente

  Verificación con otras clases (mismo ratio):
    Clase 5 (gastos): $32,767M / $6,543M = 5.008×
    Costos IO v10 / IO v10 = 1.000003 → ambos inflados igual → doble conteo simétrico

  Causa: el BP incluye cuentas en todos los niveles del PUC:
    4135   COMERCIO AL POR MAYOR   $33,082M  ← PADRE (saldo acumulado)
    413506 PRODUCTOS LÁCTEOS       $33,082M  ← HIJO (mismo dato desaglosado)
    41350601 LECHE ENTERA          $20,000M  ← NIETO
    41350602 QUESOS                $13,082M  ← NIETO
    SUMA EXTRACTOR v10 = 33,082 + 33,082 + 20,000 + 13,082 = 99,246M ≈ 99,431M ✓

ALGORITMO C5:
  PASO 1: Construir set de todos los códigos normalizados del archivo.
    normalizeCode(c) = c.replace(/[.-\s]/g,'').replace(/^0+/,'')

  PASO 2: Para cada código X, verificar si es padre:
    parentCodes[X] = true  si existe Y tal que:
      normalizeCode(Y).startsWith(normalizeCode(X)) && Y.length > X.length

  PASO 3: Filtrar rawDataLeaf = rawData.filter(d → !parentCodes[normalizeCode(d.cod)])

  PASO 4: Si rawDataLeaf.length = 0 (caso borde: BP solo raíces), revertir a rawData.

  RESULTADO: Solo las cuentas hoja (sin hijos) entran al cálculo.
    Ningún valor se cuenta dos veces.
    Si el BP ya venía resumido al nivel hoja → ninguna cuenta se elimina → correcto.

CASOS MANEJADOS:
  BP completo con 3+ niveles: elimina padres y abuelos → solo hojas
  BP resumido a 4 dígitos (nivel único): ninguna cuenta es padre → sin cambios
  BP mixto (algunos prefijos expandidos, otros no): elimina solo los expandidos
  BP de columna NSF ya procesado: sin jerarquía → sin cambios

NOTA SOBRE C1 CON C5:
  El test de suma cero (C1) se ejecuta DESPUÉS de C5, sobre las hojas filtradas.
  Esto garantiza que la suma algebraica sea representativa del BP real,
  no de las cuentas infladas con doble conteo.

CAMBIOS TECNICOS v17 vs v10
════════════════════════════════════════════════════════════════════

1. extractAndValidateBP() — nueva función normalizeCode():
   Limpia puntos, guiones y espacios de formato de los códigos.
   Elimina ceros iniciales para comparación robusta.

2. extractAndValidateBP() — construcción de allCodes (set O(1)):
   Un set de todos los códigos normalizados del archivo.
   Permite verificar si un código existe en O(1).

3. extractAndValidateBP() — construcción de parentCodes:
   Para cada código Y, itera sus prefijos de longitud 1 a len(Y)-1.
   Si el prefijo existe en allCodes → marcarlo como padre.

4. extractAndValidateBP() — rawDataLeaf:
   Filtra rawData excluyendo los padres.
   Calcula removedParents y c5Note para el panel C4.

5. C1 ejecutado sobre rawDataLeaf (no sobre rawData):
   sumaAlg, sumaC1, sumaByClass calculados sobre hojas.

6. sheetDiagnosis ampliado: rawRows, leafRows, removedParents, c5Note.

7. handleModalFile() — panel C4 actualizado:
   Muestra C5 como primer bloque del panel (antes de C1).
   "Hoja: BP2023 · 6,797 filas raw → 2,297 hojas PUC"
   Barra azul C5 con cuenta de padres eliminados.

8. Header API — nueva línea REGLA C5:
   El agente recibe la instrucción explícita de sumar directo
   sin filtros adicionales de nivel (ya fue hecho por C5).

9. MASTER_SYS VALIDACION PREVIA — ítem 1 menciona C5 primero.
